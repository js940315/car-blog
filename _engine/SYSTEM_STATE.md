### ★★★ 이번에 재확인·해결한 버그 — `photo`(파일명 직접지정) 슬롯은 실내 카운트에 안 잡힌다
`validate_image_structure`의 실내 판정은 `photo_category`가 "실내"로 시작하는지만 본다
(`_engine/build_posts.py:467-468`). 그런데 이 세션은 처음에 교차 브랜드 비교 기사 10건
전부를 `photo` 파일명 직접지정으로만 채우고 `photo_category`를 생략했다 — 실내 사진을
분명히 넣었는데도 1차 빌드에서 **10건 전부 "실내 사진 0장"** 경고가 떴다. 원인은
`photo`가 있으면 카테고리 자동교정·브랜드통일 로직들은 다 건너뛰지만, 실내 카운트 자체는
`photo_category` 문자열만 보고 세기 때문이었다. **해결**: 실내로 쓰려는 슬롯마다
`photo`(실제 파일)와 `photo_category`(반드시 "실내"로 시작하는 라벨, 예: "실내GV70")를
**둘 다** 채우는 방식으로 고쳤다 — `photo`가 있으니 브랜드통일·실사섞기 등 자동교정은
여전히 건너뛰고, `photo_category`의 "실내" 접두어만으로 카운트를 통과시켰다. 재빌드 후
`규격 위반 없음 — 전 기사 통과`로 정상화. **다음 세션 교훈**: 교차 브랜드 비교나 희소
버킷 때문에 `photo`를 직접 지정하더라도, 실내로 쓸 슬롯에는 `photo_category`에 "실내"로
시작하는 라벨을 반드시 병기할 것 — 안 그러면 사진은 맞게 넣었는데도 매번 이 경고가 뜬다
(9세션 넘게 이어진 실내 슬롯 워크어라운드와 같은 맥락의 문제이나, 이번엔 `photo` 직접지정
조합에서 처음 명시적으로 재현·해결했다).

### 본문 작성 중 발견한 실수 — 문장 구분자(`|`)에 마침표를 안 넣어 줄글처럼 나올 뻔했다
본문을 문장 리스트로 조립하는 헬퍼 함수에서 문장 끝에 마침표를 안 붙이고 그냥 `|`로만
구분했더니, `flow_group`이 문장들을 공백으로만 이어붙여 "...습니다 ...입니다 ...했습니다"처럼
마침표 없는 줄글로 렌더링됐다(1차 빌드 결과물을 Read로 직접 열어보다가 발견). 헬퍼 함수를
고쳐 마침표가 없는 문장 끝에 자동으로 `.`을 붙이도록 수정한 뒤 재생성해 해결했다.
**다음 세션 교훈**: 문장을 리스트로 조립할 때는 각 문장이 `.`, `!`, `?`, 인용부호 중 하나로
끝나는지 반드시 확인할 것 — `body_paragraphs`의 각 원소는 `flow_group`이 공백 하나로만
이어붙이므로, 마침표가 빠지면 최종 결과물이 문장 구분 없는 줄글처럼 보인다. 1번 기사를
빌드하자마자 `output/{MMDD}/1/0번 본문.txt`를 Read로 직접 열어 눈으로 확인하는 습관이
이번에도 문제를 조기에 잡아냈다.

2. **6% 기준이 기업인 사진에는 과했다.** 연예인은 레드카펫 클로즈업이라 20%씩 나오지만,
   정의선·블루메·왕촨푸는 Commons 에 행사장 **원거리 컷**뿐이라 2~5%다. 버릴 게 아니라
   원본이 크면 **얼굴 중심으로 잘라 쓰면 되는 사진**이었다.
   → `crop_to_face()` 신설: 얼굴을 프레임 20% 가 되게 정사각 크롭(합성 검증에서
     2.0% → 18.9%, 얼굴 중심 세로 40% = 인물사진 표준 구도). 크롭이 안 될 때만 버린다.
   ※ 처음엔 창을 위로 올려 **머리 위 여백만 커지는** 반대 동작이었다 — 부호를 실측으로 잡았다.

**그 과정에서 내가 낸 회귀**: `--audit --fix` 1차 버전이 크롭 복구 없이 바로 지워서
정의선이 **0장**이 됐다(현대차 오너 = 가장 자주 나올 인물). git 에서 복원하고 두 가지를 고쳤다:
  · 삭제 전에 **크롭 복구를 먼저 시도**한다.
  · 크롭도 실패하면, 그게 **그 버킷의 마지막 한 장이면 지우지 않고 경고만** 한다
    (없는 것보다 약한 사진이 낫고, 버릴지는 사람이 정한다).
  · index 에 없는 인물 파일(수동 투입·git 복원)도 감사 대상에 넣고 자동 등록한다 —
    안 그러면 파일은 있는데 `person_buckets()` 가 못 봐서 '사진 없는 인물'이 된다.
※ 기존 재고는 이미 1400px 로 축소돼 있어 크롭 여지가 없다(창 415~641px). **신규 소싱은
  원본에서 크롭**하므로 정상 동작한다. 정의선·머스크 등은 429 가 풀린 뒤 `--add` 로 다시 받을 것.
