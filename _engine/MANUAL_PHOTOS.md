# 수동 프레스 사진 투입 가이드 (속보용)

자동 소싱(무료 라이선스)은 **갓 공개된 신차·스파이샷**을 못 구할 때가 있다.
그럴 때 사장님이 제조사 프레스킷 사진 등을 **직접 넣는** 방법이다. (저작권 판단·책임은 사용자)

시스템은 넣은 사진을 나머지와 똑같이 다룬다 — 정사각 1400px 가공, 크롭·톤 변주, 순환까지 그대로.

---

## 방법 A — 그 모델을 앞으로도 쓸 때 (추천·기본)
그 사진을 **모델 버킷 풀에 추가**한다. 한 번 넣으면 이후 그 모델 글마다 자동으로 쓰인다.

1. 사진을 `assets/photos/` 에 저장. **파일명 = `<모델명>_아무거나.jpg`**
   - 기존 모델이면 그 이름 그대로: `팰리세이드_press_0.jpg`, `GV80_new_1.jpg`
   - 새 모델이면 새 이름으로 새 버킷 생성: `GV90_0.jpg`, `아이오닉9_press_0.jpg`
   - (첫 `_` 앞부분이 카테고리가 된다)
2. 등록:
   ```
   python _engine/build_photo_library.py --register
   ```
   → index에 없던 사진을 자동 등록(정사각 1400px 가공 포함). 카테고리는 파일명에서 추출.
3. 커밋 (사진 폴더는 .gitignore라 강제 추가 필요):
   ```
   git add -f assets/photos/GV90_0.jpg
   ```
4. 이제 그 모델 기사에서 `photo_category: "GV90"` 로 자동 사용됨. 여러 장 넣으면 순환·변주까지 적용.

## 방법 B — 딱 이 글 하나만 (일회용 핀)
오늘 이 포스트에만 특정 사진을 강제로 쓰고 싶을 때. 등록 불필요.

1. 사진을 `assets/photos/` 에 저장 (예: `today_hero.jpg`).
2. 그날 articles.json 의 해당 이미지 스펙에 `photo` 필드로 파일명을 직접 지정:
   ```json
   { "type": "thumbnail", "line1": "...", "line2": "...", "photo": "today_hero.jpg", "accent_words": ["..."] }
   { "type": "photo_card", "eyebrow": "...", "headline_lines": ["..."], "photo": "today_rear.jpg" }
   ```
   → `photo`가 있으면 순환을 무시하고 그 파일을 그대로 쓴다(resolve_photo). 규격이 안 맞으면 build가 크롭한다.

---

## 언제 어느 걸 쓰나
- **속보 신차를 앞으로 계속 다룰 것 같다** → 방법 A (풀에 넣어두면 두고두고 재사용 + 반복 방지 자동)
- **오늘 딱 한 번, 이 사진만** → 방법 B (핀)

## 주의
- 사진 폴더(assets/photos)는 .gitignore 대상 → **반드시 `git add -f`** 해야 클라우드 루틴이 받는다.
- 외관 hero는 그 모델이 맞아야 하고, 실내는 브랜드가 맞아야 한다(타 브랜드 로고 노출 금지).
- 저작권: 무료 라이선스가 아닌 사진은 사용자 책임하에 넣는다. 자동 루틴이 긁어오지는 않는다.
